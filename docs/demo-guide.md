# JobFit 三分钟现场演示指南

## 演示前检查

1. 使用 1440 × 900 或 1920 × 1080 的浏览器窗口。
2. 浏览器缩放保持在 90%—100%，保证页面文字清晰。
3. 使用项目内置的虚构示例，不展示真实简历、API Key、`.env`、终端代理配置或个人投递记录。
4. 关闭无关通知、聊天窗口和含个人信息的浏览器标签页。
5. 提前打开 `http://localhost:8501`，确认大模型复选框默认选中。

## 流程与口述要点

### 0:00—0:20 项目定位

画面：停留在 JobFit 首页顶部。

讲稿：

> JobFit 是一个面向 AI 应用和数据岗位的简历匹配助手。它接收一份岗位描述和一份简历，输出可解释的匹配分、已匹配技能、缺口技能以及下一步改进建议。

### 0:20—0:40 技术思路

画面：简要展示 README 中的架构图，或者停留在首页的功能标签。

讲稿：

> 项目使用规则和大模型分工。规则层负责技能抽取、TF-IDF 岗位检索和可解释打分；大模型负责理解语义和生成理由。大模型返回结果会经过 JSON 结构校验，失败时自动回退到规则模式。

### 0:40—1:25 一键体验与规则结果

操作：

1. 点击“填入 AI 应用示例”。
2. 关闭“启用大模型语义增强”。
3. 点击“开始岗位匹配分析”。
4. 向下展示匹配分、雷达图和技能缺口。

讲稿：

> 我点击示例按钮后，JD 和脱敏简历会自动填入。先关闭大模型，体验完全离线的规则模式。规则分由技能覆盖率和文本相似度加权得到。这里能直接看到哪些技能已经命中，哪些要求还没有在简历中出现。

### 1:25—2:05 大模型语义增强

操作：

1. 打开大模型增强。
2. 再次点击分析。
3. 对比规则参考分和 DeepSeek 综合分。
4. 展示评估依据和下一步建议。

讲稿：

> 现在开启 DeepSeek。大模型会结合完整 JD、简历、抽取出的技能和相似岗位，补足关键词匹配看不到的语义信息。页面会同时保留规则参考分，避免把两套评分混在一起。模型结果还会经过字段、类型、分数范围和技能冲突校验。

### 2:05—2:35 评测结果

操作：切换到 README 的“实际结果”部分。

讲稿：

> 我还建立了 30 组公开合成评测样本，high、mid、low 各 10 组。规则模式准确率是 76.67%，DeepSeek 模式在同一次运行中达到 86.67%。除了总体准确率，我也记录了 Macro F1、分类指标和混淆矩阵，用来定位中间匹配档和高低匹配的误判。

### 2:35—2:55 局限和 Roadmap

操作：展示 README 的“已知局限”或 Roadmap。

讲稿：

> 当前检索仍使用字符级 TF-IDF，对同义改写不够稳定；评测集也是合成数据。下一步会尝试向量 Embedding 检索、PDF 简历解析和更大规模的岗位语料。

### 2:55—3:00 收尾

画面：回到 JobFit 结果页。

讲稿：

> 这就是 JobFit：一个可运行、可解释，也经过量化评测的 AI 岗位匹配原型。

## 演示注意事项

- 本指南用于现场演示、面试口述或自行练习，不要求录制视频。
- 全程控制在 3 分钟左右，优先展示规则模式与大模型模式的差异。
- 评测结果只讲总体准确率、Macro F1 和主要混淆类型，不需要逐格念矩阵。
- 被问到局限时，主动说明字符级 TF-IDF、合成评测集和模型结果波动。
